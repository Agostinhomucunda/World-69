# Radar World 69 — evidências de fontes e arquitetura

Verificação: 1 de outubro de 2026. Os dados devem ser obtidos por API/feed autorizado, nunca por scraping de páginas protegidas. A integração mantém a atribuição e o link original, mostra apenas campos realmente disponíveis e conserva um estado vazio honesto quando não há resultados.

## Fontes viáveis para a primeira versão

- **Jobicy (vagas remotas)** — API oficial: <https://jobicy.com/jobs-rss-feed>. GET público sem chave, até 200 vagas por chamada, filtros por localização/categoria/termo e campos de empresa, elegibilidade, tipo, resumo, publicação e salário quando fornecidos. Os termos permitem integrar listagens em websites sem aprovação individual, desde que Jobicy continue identificado como fonte e a URL canónica da listagem seja preservada. A API deve ser consultada no máximo uma vez por hora; os links diretos para ATS podem exigir uma API comercial paga e não serão comprados nem utilizados.
- **Remote OK (vagas remotas)** — FAQ oficial: <https://remoteok.featurebase.app/help/articles/3140840-is-there-an-api-or-rssjson-feed-of-remote-jobs>; feed JSON: <https://remoteok.com/api>. JSON/RSS públicos, gratuitos e sem autenticação. Para agregadores, é exigido crédito à Remote OK e link de volta para cada anúncio original; o JSON do próprio feed declara que o link deve ser dofollow. Não usar o logótipo da marca sem autorização. A integração deve usar o URL original, `noopener noreferrer` sem `nofollow`, e nunca copiar o feed como se fosse original do World 69.
- **We Work Remotely (vagas remotas)** — instruções oficiais: <https://weworkremotely.com/remote-job-rss-feed>. O feed RSS público pode ser usado por qualquer pessoa, com link/atribuição ao WWR e à listagem. Há feed geral e feeds por categoria.
- **ReliefWeb/OCHA (emprego, formação e desenvolvimento humanitário)** — API e termos oficiais: <https://reliefweb.int/help/api>; documentação atual: <https://apidoc.reliefweb.int/>. A API pública serve Reports, Jobs e Training em tempo real, sem taxas, exige `appname`, e limita a 1.000 entradas por chamada e 1.000 chamadas por dia. Os registos podem conter material protegido de parceiros: preservar a origem e o URL original, não republicar corpos extensos sem verificar os direitos da fonte original. A versão `v0` da documentação é obsoleta e não deve ser usada.
- **Bluesky (publicações sociais públicas)** — API oficial: <https://docs.bsky.app/docs/api/app-bsky-feed-search-posts>. A documentação do AppView indica que a maioria dos GETs `app.bsky.*` é pública e pode ser consultada sem autenticação em `https://public.api.bsky.app`. Tratar as publicações como pistas comunitárias não verificadas; guardar/exibir apenas excerto curto, omitir perfis e contactos pessoais, manter o link original e não copiar HTML.
- **GitHub Issues (contribuições e projetos open source)** — pode ser consultado através da API pública oficial de Issues/Search usando o token já fornecido ao workflow do GitHub Actions. Só classificar como contribuição ou projeto; nunca presumir remuneração. Cada item mantém link para a issue e o repositório. Verificar limites e filtros nos docs oficiais antes de acrescentar o adaptador.
- **Greenhouse Job Board API (páginas de carreiras oficiais)** — docs: <https://developers.greenhouse.io/job-board.html>. GETs de cada `board_token` são públicos e sem autenticação; a cobertura é por empresa/board conhecido, não é um catálogo global. Ativar apenas para boards identificados em páginas oficiais de carreira; não enviar candidaturas.

## Fontes condicionadas ou adiadas

- **USAJOBS** — documentação oficial: <https://developer.usajobs.gov/tutorials/search-jobs>. É necessário pedir uma API key e enviar `Host`, `User-Agent` e `Authorization-Key`; a documentação descreve até 500 resultados por pedido. Manter como adaptador configurável/desativado até o proprietário obter e configurar a chave no segredo do repositório; não preencher a inscrição em nome do utilizador.
- **Arbeitnow** — o fundador descreve um endpoint de empregos gratuito, sem chave e focado em Alemanha/Europa e Reino Unido: <https://www.arbeitnow.com/blog/job-board-api>. O material consultado não apresenta claramente uma licença/termos de republicação; não ativar até esclarecer a permissão, ou limitar-se ao URL e metadados se os termos oficiais confirmarem isso.
- **Remotive** — condições oficiais: <https://remotive.com/remote-jobs/api>. A API pública apresenta atraso de 24 horas, exige link e menção à Remotive e proíbe explicitamente submeter anúncios da Remotive a websites de terceiros. Como o Radar é um website de terceiros, não integrar sem autorização escrita.
- **Mastodon** — docs: <https://docs.joinmastodon.org/methods/search/>. A pesquisa de status varia por instância; pesquisa textual completa pode depender de backend e autenticação. Não alegar cobertura federada total nem raspar instâncias.
- **Reddit** — termos oficiais: <https://redditinc.com/policies/data-api-terms>. Requer registo/identificação de desenvolvedor e cumprimento dos Data API/Developer Terms. Deixar desativado até existir credencial e verificação de autorização para o uso pretendido.
- **LinkedIn, X, Facebook e Instagram** — não tratar páginas públicas como feeds livres. A integração depende das APIs oficiais, permissões e credenciais comerciais aplicáveis; não fazer scraping nem contornar login ou limites.

## Arquitetura, atualização e métricas

Na inspeção inicial, a homepage era HTML/CSS/JavaScript estático sem `package.json`, `netlify.toml` nem diretório de Functions; o coletor de catálogo já usava GitHub Actions de hora em hora e commits condicionais para `main`. Esta branch acrescenta `package.json`, uma função Netlify Functions/Blobs e o rewrite same-origin em `netlify.toml`, além do workflow horário do Radar, que atualiza os JSON estáticos apenas quando há mudança. A cadência respeita o limite máximo de uma chamada por hora do Jobicy.

A documentação Netlify Functions/Blobs foi consultada: <https://docs.netlify.com/build/functions/overview/> e <https://docs.netlify.com/build/data-and-storage/netlify-blobs/>. Functions permitem executar código server-side sem servidor dedicado; Blobs oferece `onlyIfNew` e `onlyIfMatch` para escritas condicionais. O endpoint implementado usa compare-and-swap, deduplicação por token aleatório do navegador/dia UTC, limite diário por item/shard e leitura real; o código não persiste IP ou identidade pessoal. A interface mantém números/ordenação por views desativados se o backend não responder.

A recolha social não deve afirmar que um post é uma vaga verificada. A interface deve etiquetar publicações como pistas comunitárias, preservar o link original e remover e-mails/telefones ou outros dados pessoais do excerto. Os anúncios formais ficam sujeitos ao estado publicado pela fonte; na ausência de prova de validade, mostrar “Estado desconhecido” ou “Pode ter expirado”, sem inventar que estão ativos.

## Correções de validação

A documentação atual do ReliefWeb identifica **v2** como a única versão ativa e declara v1 desativada. Desde 1 de novembro de 2025, é necessário um `appname` pré-aprovado. Portanto, o Radar não deve chamar ReliefWeb com um nome inventado; a fonte fica configurável e desativada até existir esse appname aprovado. A API continua pública e gratuita, mas a aprovação do identificador é um pré-requisito.

A API oficial Bluesky confirma que a maioria dos GETs AppView é pública e sem token. Um pedido de teste ao `public.api.bsky.app` recebeu 403 HTML do BunnyCDN no sandbox (cabeçalho `cdn-requestcountrycode: JM`), não uma resposta de autenticação da API. A integração pode existir como adaptador público com falha isolada, mas a recolha não pode ser declarada confirmada até funcionar no runner agendado; se o 403 persistir ali, a fonte deve aparecer como indisponível e não produzir resultados.

O endpoint oficial GitHub Search Issues respondeu com resultados públicos e documenta no máximo 100 resultados por página e até 30 pedidos autenticados/minuto. Usar filtros explícitos `is:issue is:open`, janela recente e labels `good first issue`/`help wanted`; classificá-los como contribuição open-source não remunerada/desconhecida, nunca como pagamento confirmado.
